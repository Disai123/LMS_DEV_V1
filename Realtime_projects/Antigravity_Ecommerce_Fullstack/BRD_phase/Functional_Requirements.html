Functional Requirements

Functional requirements define what the system must do to meet the business objectives. These requirements describe the system's behavior and functionality from the user's perspective.

🛍️ Product Discovery & Selection

Product Browsing (US-001)

Browse products with filtering options to find products that match preferences and budget

Acceptance Criteria:

  • • View products in responsive grid layout
  • • Filter by category, price range, and attributes
  • • Search using keywords with real-time suggestions
  • • Sort by price, popularity, and rating
  • • Navigate through paginated results
Product Information (US-002)

View detailed product information to make informed purchase decisions

Acceptance Criteria:

  • • Product image, name, description, and price
  • • Category and current stock count
  • • Add to cart from the details page
  • • Clear message when the product is out of stock
Smart Search (US-003)

Search for products with intelligent suggestions for quick discovery

Acceptance Criteria:

  • • Search products by name or keyword
  • • Filter listing by category and price
  • • Sort products when the listing supports it
  • • Show a clear empty state when nothing matches

🛒 Shopping Cart & Checkout

Shopping Cart Management (US-004)

Manage items in shopping cart to review and modify purchases before checkout

Acceptance Criteria:

  • • Add a product while logged in
  • • View cart items, quantities, and cart total
  • • Increase, decrease, or remove a line
  • • Block a quantity above available stock
Simple Checkout (US-005)

Place an order from the cart without a payment gateway

Acceptance Criteria:

  • • Start checkout while logged in
  • • Enter delivery information
  • • Review items and total
  • • Place the order in the app
  • • See order confirmation data
Order Confirmation (US-006)

Receive clear order confirmation and tracking information

Acceptance Criteria:

  • • Confirmation page with order number and items
  • • Cart is cleared after a successful order
  • • Stock is reduced for purchased items
  • • Customer can open the same order later in history

👤 Customer Account Management

User Authentication (US-007)

Create and manage account for personalized features and order tracking

Acceptance Criteria:

  • • Register with email and password
  • • Log in as customer or admin
  • • Receive a FastAPI JWT for later requests
  • • Log out and clear the session
Order History & Tracking (US-008)

View order history and track orders for purchase monitoring

Acceptance Criteria:

  • • View the customer's own order history
  • • See each order's current status
  • • Open an order to see its items and total
Profile Management (US-009)

Manage profile and preferences for customized shopping experience

Acceptance Criteria:

  • • View the logged-in profile
  • • Update basic account details
  • • Keep profile data in PostgreSQL

📊 Admin Catalog & Orders

Product Management (US-010)

Admins add, edit, and delete products in the catalog

Acceptance Criteria:

  • • Admin can add a product with name, price, stock, and category
  • • Admin can edit an existing product
  • • Admin can delete a product
  • • Customer listing shows the updated catalog
Order Management (US-011)

Manage customer orders efficiently for processing and customer satisfaction

Acceptance Criteria:

  • • View customer orders in the admin area
  • • Open an order to see items and customer
  • • Update order status
  • • Customer history shows the new status
Category Management (US-012)

Admins add, edit, and delete product categories

Acceptance Criteria:

  • • Admin can add a category
  • • Admin can edit a category name
  • • Admin can delete a category that is not required
  • • Products can be assigned to a category

📋 Business Rules

Authentication & Security
  • • Cart, checkout, and profile require a logged-in customer
  • • FastAPI issues a JWT after login
  • • Passwords are stored hashed in PostgreSQL
  • • Admin routes require an admin user
Order Processing
  • • Stock is checked before an order is placed
  • • Quantity cannot exceed available stock
  • • Placing an order writes order and order_items rows
  • • The cart is updated after a successful order
Product Management
  • • Products belong to a category
  • • Stock is stored on the product row
  • • Only admins can create, edit, or delete products
  • • Sample catalog data is enough to test the store
Customer Experience
  • • Cart is stored in PostgreSQL for the logged-in user
  • • Checkout collects delivery information only
  • • No guest checkout and no payment gateway
  • • Empty cart and failed login show a clear message
