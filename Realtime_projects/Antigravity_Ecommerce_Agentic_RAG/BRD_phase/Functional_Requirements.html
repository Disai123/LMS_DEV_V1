Functional Requirements

These requirements describe what the Agentic RAG assistant must do. The knowledge source is approved product manuals, user manuals, usage guides, FAQs, warranty text, and similar documents. Answers must be grounded and cited.

📄 Document Knowledge Base

Ingest Approved Documents (FR-RAG-001)

The system loads approved manuals and related product documents.

Acceptance Criteria:

  • • Supports the document formats already used in the project
  • • Extracts text and removes obvious noise
  • • Attaches metadata such as document name, product, and section
  • • Does not create a second store catalog database
Chunk and Embed (FR-RAG-002)

Documents are split with chunk size and overlap, then converted to embeddings.

Acceptance Criteria:

  • • Chunks keep enough overlap to preserve meaning
  • • Each chunk maps back to its source document
  • • Embeddings are stored in a FAISS index
  • • The index can be rebuilt when manuals change

🔎 Retrieval and Grounded Answers

Ask via POST /rag/ask (FR-RAG-003)

Users ask product questions from the React chat UI.

Acceptance Criteria:

  • • React chat posts to FastAPI POST /rag/ask
  • • Optional product context is passed from a product page
  • • Existing auth is reused
  • • Existing store APIs are not changed
Agentic Retrieval (FR-RAG-004)

The agent understands the question, may rewrite the query, and searches FAISS.

Acceptance Criteria:

  • • Retrieves the best matching chunks with metadata
  • • Checks whether the retrieved context is relevant
  • • Retries retrieval once with a better query when needed
  • • Uses a relevance threshold so weak matches are dropped
Citations and Refusal (FR-RAG-005)

Answers must cite sources and refuse when documents do not support the claim.

Acceptance Criteria:

  • • Answer uses only retrieved approved content
  • • Source shows document name and section when available
  • • If nothing useful is found, the assistant says so
  • • Never invents specs, warranty terms, or safety guidance

🛡️ Scope and Safety

Reuse the Existing Store (FR-RAG-006)

The existing React frontend and FastAPI backend stay the base.

Acceptance Criteria:

  • • Existing login and catalog remain in place
  • • The store UI is not redesigned
  • • Cart, checkout, and order flows stay unchanged
  • • This is not a SQL Q&A bot over orders or customers
Clarification and Injection Safety (FR-RAG-007)

Vague questions get a short clarification. Prompt injection is treated as untrusted input.

Acceptance Criteria:

  • • Ask a short clarification instead of guessing
  • • Ignore instructions hidden in user text or retrieved documents
  • • Do not expose secrets or internal prompts
