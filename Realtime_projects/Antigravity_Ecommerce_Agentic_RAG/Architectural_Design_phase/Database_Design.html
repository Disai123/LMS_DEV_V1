Document Index Design

The knowledge store for this feature is a FAISS vector index of document embeddings, not a second store catalog. Existing product and user tables stay as they are. Manuals, FAQs, and warranty files are chunked, embedded, and mapped back to source metadata.

📄 Approved Document Record 

Document
  id              local file or document id
  name            Headphones User Manual
  product_name    Premium Wireless Headphones
  type            manual | faq | warranty | usage guide
  source_path     local approved-documents folder
Rules:
  • Only approved product documents are ingested
  • Do not copy the store catalog into a new database
  • Reuse existing product names when attaching metadata

✂️ Chunk + Embedding Record 

Chunk
  chunk_id        unique id
  document_name   Headphones User Manual
  product_name    Premium Wireless Headphones
  section         Pairing
  text            cleaned chunk text
  embedding       vector used by FAISS
  source_location page or heading when available
Why this exists:
  • Chunk size and overlap keep enough context for retrieval
  • Embeddings let FAISS find similar manual text
  • Metadata becomes the citation on the answer

🗂️ FAISS Index Layout

Index files

Keep the FAISS index and a metadata file in a clear local folder. Rebuild both when manuals change.

Lookup

FAISS returns vector ids. Metadata maps each id to document, product, section, and chunk text.

Existing store tables

Login and catalog stay on the existing backend. This feature does not create a second store database.

📊 Rebuild and Retrieval

Rebuild
  • Ingest new manuals
  • Re-chunk and re-embed
  • Write a new FAISS index
Query
  • Embed the user question
  • Search FAISS
  • Filter by relevance threshold
