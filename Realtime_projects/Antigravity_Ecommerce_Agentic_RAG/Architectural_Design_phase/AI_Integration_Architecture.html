RAG Agent Architecture

LangChain and LangGraph run a small Agentic RAG flow. The agent understands the question, searches FAISS, checks retrieved context, retries once if needed, and writes a grounded answer with citations.

🤖 Agent Roles

Understand the question
  • Detect product, topic, and whether a search is needed
  • Use product context from a product page when present
  • Ask a short clarification instead of guessing
Grounding rule
Answer only from retrieved approved documents.
If the manuals do not support the answer, say so.
Never invent specs, warranty conditions, or safety guidance.
Include document name and section as citations.

Flow
1. Receive the question on POST /rag/ask
2. Understand product and topic
3. Rewrite the search query
4. Retrieve chunks from FAISS
5. Check relevance
6. Retrieve again once if context is weak
7. Answer only from retrieved content
8. Return citations or a not-found message

💾 Context Selection

Retrieved manuals only

The answer step sees selected chunks and their metadata. It does not browse the open web.

Langfuse
  • Trace embedding, retrieval, retry, and answer
  • Score retrieval relevance, grounding, and citations
  • Langfuse does not replace runtime safety checks

⚙️ Error Handling

No useful chunks

Return a clear not-found message. Do not invent an answer.

Index errors

If FAISS or embeddings fail, show a simple error and keep the store working.

Prompt injection

Treat user text and retrieved document text as untrusted.
