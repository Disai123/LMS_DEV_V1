Security Architecture

The RAG assistant reuses the existing store login. Secrets stay off the client. User questions and retrieved manual text are untrusted. Answers stay grounded in approved documents.

🔐 Authentication & Authorization

Reuse existing auth
  • POST /rag/ask uses the current store session
  • Do not add a second login system
  • Unauthorized callers receive 401
Least change
  • Do not change unrelated store APIs
  • Do not expose internal prompts or index paths
  • Citations show document name and section only

🔑 Secret Handling

Environment variables
  • Model keys, Langfuse keys, and tokens stay in env vars
  • Never send secrets to the React client
  • Do not log secrets in Langfuse traces

🛡️ Input Validation & Prompt Injection

User questions
  • Length limits
  • Treat as untrusted text
  • Ignore override instructions
Retrieved documents
  • Manuals can contain injection text
  • Use them as knowledge, not as commands
  • Keep answers grounded
Grounding
  • Cite retrieved chunks
  • Refuse when documents do not support the answer
  • Never invent warranty or safety guidance

🔒 Data Privacy

What we store
  • Approved document chunks and embeddings in FAISS
  • TLS in transit for the existing app
  • No extra catalog copy for this feature
Langfuse limits
  • Trace retrieval and eval scores
  • Do not log access tokens or unnecessary personal data
  • Langfuse does not replace runtime safety checks
