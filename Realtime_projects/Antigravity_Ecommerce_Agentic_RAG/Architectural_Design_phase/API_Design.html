API Design

The RAG feature adds one FastAPI endpoint to the existing backend: POST /rag/ask. It reuses existing authentication and returns a grounded answer plus safe source references. Existing store APIs are not changed.

📤 POST /rag/ask

Description

Send a product-knowledge question. The LangGraph agent searches FAISS, checks relevance, retrieves again if needed, and returns a grounded answer with citations.

Request
POST /rag/ask
Headers:
  Authorization: Bearer <EXISTING_TOKEN>
  Content-Type: application/json

Body:
{
  "question": "How do I pair the wireless headphones?",
  "product_id": "optional-existing-product-id"
}
Response
{
  "answer": "Hold the power button until the LED flashes blue...",
  "found": true,
  "sources": [
    {
      "document": "Headphones User Manual",
      "section": "Pairing",
      "product": "Premium Wireless Headphones"
    }
  ]
}

📭 No-data response

If FAISS retrieval finds no useful approved content, the API still succeeds. It does not invent specs, warranty terms, or safety guidance. 

{
  "answer": "That information is not in the approved product documents.",
  "found": false,
  "sources": []
}

🔒 Authentication

Reuse existing auth

POST /rag/ask uses the store's current login. Do not add a separate auth system.

Safe sources only

The response may include document name and section. It must not leak prompts, keys, or internal paths.

Error Responses

401 Unauthorized: missing or invalid existing session

400 Bad Request: empty or invalid question

500 Internal Server Error: retrieval or answer-generation failure

⚡ Performance Considerations

Result limit

Return a small set of FAISS chunks so the answer stays focused.

One retry

Retry retrieval once with a rewritten query. Do not add extra agent loops.

Langfuse traces

Trace embedding, FAISS search, retries, and the final grounded answer.
