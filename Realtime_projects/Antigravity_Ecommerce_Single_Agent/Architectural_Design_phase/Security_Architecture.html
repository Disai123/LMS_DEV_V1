Security Architecture

Ask the Store reuses the existing FastAPI login and permissions. The agent is read-only. User questions are untrusted. Secrets, SQL, and system prompts never appear in the answer.

🔐 Authentication & Authorization

Reuse Existing Login
  • POST /agent/ask uses the current FastAPI authentication
  • Unauthenticated requests are rejected
  • Customer and admin roles keep existing access rules
  • We do not add a second identity system
Data Visibility
  • The agent only reads data the signed-in user may see
  • Customer questions stay inside that customer's allowed orders
  • Staff totals still follow existing admin permissions
  • The agent cannot write cart, order, or stock rows

🔑 Secret Protection

Environment Values
  • LLM, database, and Langfuse keys stay in environment variables
  • Secrets never appear in React, answers, or logs
  • System prompts and internal config are not returned to the user
  • Different keys for local and Render environments
Key Rotation

Rotate secrets by updating environment values on Render. Do not put real keys in DEPLOYMENT.md.

🛡️ Input Validation and Prompt Injection

User Questions
  • Treat every question as untrusted
  • Limit length and retries
  • Refuse injection attempts
Approved Data Requests
  • Validate the planned read before it runs
  • Allow only approved tables and fields
  • Reject write operations
Database Queries
  • Use parameterized reads
  • Never return raw SQL to the user
  • Keep result size bounded

🔒 Data Privacy

Customer Information
  • Protect customer records with existing authorization
  • Do not log unnecessary personal data
  • Encrypt traffic with TLS in production
  • Langfuse must not store passwords, keys, or extra customer details
Langfuse Does Not Replace Runtime Checks
  • Langfuse traces the agent after the feature works
  • Authentication, permissions, and read-only rules stay in FastAPI
  • Evaluation scores do not replace a refused unsafe request

🚦 Limits and Abuse Prevention

Request Limits

Keep query time, retries, and result size under the project limits.

Useful Logging

Log request IDs and outcomes. Do not log secrets or extra sensitive fields.

Input Length Limits

Reject oversized questions before they reach LangGraph.
