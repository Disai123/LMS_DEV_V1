Security Architecture

Security is paramount for the AI agent, ensuring user data privacy, API key protection, and secure communication between all system components.

🔐 Authentication & Authorization

JWT Token Validation
  • All API endpoints require valid JWT token
  • Token validated via middleware before request processing
  • User ID extracted from token payload
  • Invalid tokens return 401 Unauthorized
User Isolation
  • Conversations isolated per user ID
  • Users can only access their own conversations
  • Cart operations scoped to authenticated user
  • No cross-user data leakage

🔑 API Key Security

Environment Variables
  • OPENAI_API_KEY stored in .env file (never in code)
  • Not exposed to frontend or client-side code
  • Only accessible in server-side API routes
  • Different keys for development and production
Key Rotation

API keys can be rotated by updating environment variables. No code changes required.

🛡️ Input Validation & Sanitization

User Messages
  • Length validation (max 2000 chars)
  • XSS prevention
  • SQL injection prevention
Tool Parameters
  • Type validation
  • Range checks (e.g., quantity > 0)
  • Required field validation
Database Queries
  • Prisma parameterized queries
  • No raw SQL with user input
  • Input sanitization

🔒 Data Privacy

Conversation Privacy
  • Conversations stored per user ID
  • No sharing between users
  • Data encrypted in transit (TLS 1.3)
  • Data encrypted at rest (database level)
OpenAI Data Usage
  • Messages sent to OpenAI for processing
  • OpenAI may use data for model training (check settings)
  • No sensitive data (passwords, payment info) in messages
  • Consider OpenAI data retention policies

🚦 Rate Limiting & Abuse Prevention

Request Rate Limiting

Limit requests per user/IP to prevent abuse and control costs.

Token Usage Monitoring

Monitor OpenAI token usage to prevent excessive costs and detect anomalies.

Input Length Limits

Enforce maximum message length to prevent token overflow and abuse.
