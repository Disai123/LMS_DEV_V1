Database Design

Ask the Store reuses the existing PostgreSQL/Neon database. The agent reads products, categories, customers, orders, order items, and stock. It does not create a second database and it does not write store rows.

🗃️ Existing Store Tables 

Approved read-only tables (already in the store):

  products
  categories
  customers / users
  orders
  order_items
  stock / inventory fields on products

The agent uses the existing FastAPI database connection.
It does not add a second schema for shopping-cart writes.
What the agent may read:
  • products: name, price, category, description, stock
  • categories: names and product counts
  • customers: counts and allowed profile fields only
  • orders / order items: counts, totals, and allowed history

🔒 Read-Only Access Path 

Agent data access rules:

  1. Use the existing connection infrastructure
  2. Allow SELECT-style reads only
  3. Limit columns to an approved list
  4. Bound result size
  5. Never expose raw SQL to the user
  6. If no row matches, return no-data
  7. Never invent a product, price, or total
What the agent must not do:
  • Insert, update, or delete store rows
  • Change cart, checkout, or order state
  • Create a second database or migration set for the agent
  • Read passwords, tokens, or secrets

🔗 How Data Is Used

Existing Store Tables Stay Primary

Catalog, cart, checkout, and admin continue to use the same tables. Ask the Store only reads them.

No New Cart Schema

Cart tables remain for the existing store UI. The agent does not write cart items.

Optional Logs

Request IDs and safe logs can be stored if the existing project already has a logging table. Langfuse later holds traces. Do not log secrets or extra customer data.

📊 Indexes and Limits

Reuse Existing Indexes
  • Product and category lookups
  • Order and customer filters already in the store
Query Limits
  • Cap rows returned to the agent
  • Keep date-range and count queries bounded
