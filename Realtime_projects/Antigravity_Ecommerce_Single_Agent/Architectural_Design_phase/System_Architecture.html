System Architecture

Ask the Store sits inside the existing e-commerce application. The store keeps serving catalog, cart, checkout, and admin as before. The new piece is one read-only LangGraph agent reached through FastAPI.

🏗️ High-Level Architecture

┌─────────────────────────────────────────┐
│ Frontend (existing ReactJS) │
│ • Ask the Store chat UI │
│ • Existing login session │
└─────────────────────────────────────────┘
↓ POST /agent/ask
┌─────────────────────────────────────────┐
│ API (existing FastAPI) │
│ • POST /agent/ask │
│ • Existing auth and permissions │
└─────────────────────────────────────────┘
↓ LangGraph
┌─────────────────────────────────────────┐
│ Agent (LangGraph + LangChain) │
│ • Check question scope │
│ • Configured LLM via LangChain │
│ • Build a safe final answer │
└─────────────────────────────────────────┘
↓ Approved read-only access
┌─────────────────────────────────────────┐
│ Store data access │
│ • Products and categories │
│ • Customers, orders, order items │
│ • Stock and sales totals │
└─────────────────────────────────────────┘
↓ Read queries
┌─────────────────────────────────────────┐
│ Database (existing PostgreSQL/Neon) │
│ • No second database │
│ • Langfuse traces added later │
└─────────────────────────────────────────┘

🔄 Request Flow

1
User asks a store question
React UI sends POST /agent/ask with the existing session
↓
2
FastAPI checks authentication
Existing login and permissions decide if the request may continue
↓
3
LangGraph checks the question
Out-of-scope or write requests stop with a refusal
↓
4
Prepare and validate the data request
Only approved store fields are requested
↓
5
Read approved PostgreSQL data
Read-only path. No cart, order, or stock writes.
↓
6
Create the final answer
The configured LLM via LangChain writes only from the query result
↓
7
Return the answer to React
Request IDs stay in logs. Langfuse can attach traces later.

🧩 Component Responsibilities

Frontend (existing React)
  • Show the Ask the Store screen
  • Send the question
  • Display the answer or status
  • Keep using existing login
FastAPI
  • Expose POST /agent/ask
  • Reuse authentication
  • Start the LangGraph run
  • Return a safe answer
LangGraph
  • Check store scope
  • Read approved data
  • Refuse write actions
  • Never invent numbers
PostgreSQL/Neon
  • Existing products and categories
  • Existing customers and orders
  • Existing stock and totals
  • No new store schema required
