AI Integration Architecture

Ask the Store uses LangGraph for the agent flow and LangChain to call the configured LLM. The graph checks the question, reads approved store data, and writes a grounded answer. It does not mutate the cart.

🤖 LangGraph and LangChain

Configured LLM
  • Runtime: LangGraph inside the existing FastAPI backend
  • Model access: configured LLM via LangChain
  • Secrets: environment values only
  • Rule: answers must come from query results, not invention
Agent Behavior

The graph stays small and read-only: 

User question
-> check whether it is a store question
-> safely prepare the data request
-> validate the data request
-> read approved store data
-> create the final answer

🔧 Approved Store Data Access

What the agent may read
Products
Counts, names, prices, categories
Categories
List categories and products in one
Stock
Read current stock for a product
Orders
Allowed order history and totals
Customers
Counts and permitted fields only
Sales totals
Order totals from stored rows
Refuse writes
No cart add, update, or checkout
Refuse unrelated
Politely say the agent only answers about the store
LangGraph flow
1. Receive the question on POST /agent/ask
2. Confirm it is an allowed store question
3. Build a read-only data request
4. Query PostgreSQL/Neon
5. If no rows, return a no-data message
6. Otherwise write the answer from those rows

💾 State and Observability

LangGraph State

Each run carries the question, scope decision, data request, query result, and final answer. An unsafe or failed step can stop the graph.

Request IDs

FastAPI attaches a request ID so logs can follow one Ask the Store call from UI to database.

Langfuse Later
  • Trace API, graph, model, and data steps
  • Score important questions after the feature works
  • Do not replace FastAPI security with traces

⚙️ Error Handling

Model Failures

If the configured LLM fails, return a safe message. Do not expose internals.

Database Failures

If PostgreSQL is unavailable, stop the graph and keep the rest of the store running.

Timeout Handling

Timeouts return a simple retry message. Existing catalog and checkout stay available.
