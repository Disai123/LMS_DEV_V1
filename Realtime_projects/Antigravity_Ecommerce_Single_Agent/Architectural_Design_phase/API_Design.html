API Design

Ask the Store adds one endpoint to the existing FastAPI backend: POST /agent/ask. Extra endpoints are not required unless the current application already needs one for this feature. Existing customer and admin APIs stay unchanged.

📤 POST /agent/ask

Description

Accept a simple user question, send it to the LangGraph agent, and return a safe answer from approved store data.

Request
POST /agent/ask
Headers:
  Authorization: existing store session or token
  Content-Type: application/json

Body:
{
  "question": "How many products are in the store?"
}
Response
{
  "answer": "The store has 12 products.",
  "status": "ok"
}

📥 Response Cases

What the endpoint returns

The body stays small. Status values tell the React UI which message style to show.

Example outcomes
{
  "answer": "No matching data was found.",
  "status": "no_data"
}

{
  "answer": "I only answer questions about the store.",
  "status": "out_of_scope"
}

{
  "answer": "I could not complete that request. Please try again.",
  "status": "error"
}

🔒 Authentication

Reuse Existing Login

POST /agent/ask uses the same authentication and authorization as the rest of the FastAPI store. We do not add a separate identity system.

Permission Boundaries

Customer and admin roles keep their existing visibility. The agent cannot read data the user is not allowed to see.

Error Responses

401: user is not authenticated

400: invalid or empty question

Safe 500-style message: model, database, or timeout failure without internals

⚡ Limits and Safety

Input Size

Reject oversized questions. Keep result size and retries under a safe limit.

Timeout Handling

If LangGraph or the database times out, return a simple safe message.

Hidden Internals

Never return secrets, SQL, stack traces, or system prompts.
