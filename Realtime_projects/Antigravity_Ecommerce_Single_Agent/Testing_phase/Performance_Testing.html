Performance Testing

Performance checks keep Ask the Store inside safe limits. Query time, result size, input size, and retries must stay bounded so the existing FastAPI store remains usable.

Limits to Verify

  • Question length is rejected when it exceeds the project limit
  • Approved data reads return a bounded number of rows
  • Retries stop after the configured maximum
  • Timeouts return a safe message instead of hanging the UI

Existing App Impact

  • Catalog, cart, checkout, and admin stay responsive while a question is running
  • The agent reuses the existing PostgreSQL connection pool
  • A failed LangGraph run does not stop FastAPI

What Not to Measure as Success

Do not treat invented speed claims as a pass. Record whether the request stayed within the documented limits and whether the answer still matched the database.
