Test Planning

Test planning lists the Ask the Store cases that must be recorded in TESTING.md. Every store-data answer is compared with PostgreSQL. Write actions are expected to fail.

📋 Test Strategy

Unit Tests

Check LangGraph scope, validation, and read-only data helpers.

Integration Tests

Call POST /agent/ask against the existing FastAPI app and PostgreSQL.

UAT in the Browser

Sign in, open Ask the Store, and confirm answers and existing store flows.

✅ Test Cases

Store Data Questions
  • How many products are in the store?
  • Show products in a selected category
  • Show stock for a selected product
  • How many orders and customers are there?
  • Sales or order totals, including a date range
Safe Behavior Tests
  • No matching data returns a no-data message
  • Unrelated questions are refused
  • Add-to-cart or checkout requests are refused
  • Prompt-injection attempts are refused
  • Unsafe database requests are blocked
App and Auth Tests
  • Unauthenticated POST /agent/ask is rejected
  • Invalid input returns a clear message
  • Model, database, and timeout failures stay safe
  • Existing Products, Cart, Checkout, Orders, and Admin still work

🎯 Success Criteria

Correctness

Store-data answers match the database. Nothing is invented.

Read-Only

The agent never changes products, stock, orders, or the cart.

Existing Store

FastAPI and React still serve the original e-commerce flows.
