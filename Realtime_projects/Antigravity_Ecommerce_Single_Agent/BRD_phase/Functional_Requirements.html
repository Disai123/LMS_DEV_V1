Functional Requirements

These requirements describe what Ask the Store must do. The agent answers questions about real store data through POST /agent/ask. It stays read-only. It does not rebuild the store or change products, orders, or stock.

🔍 Product and Category Questions

Product Lookup (FR-ATS-001)

Signed-in users can ask about products using natural language

Acceptance Criteria:

  • • User can ask questions such as "How many products are in the store?"
  • • Agent reads approved product data from the existing PostgreSQL database
  • • Answers use real product names, prices, and categories only
  • • If no product matches, the agent says no matching data was found
  • • The agent never invents a product or price
Product Details Query (FR-ATS-002)

Users can ask for details of a selected product

Acceptance Criteria:

  • • User can ask about price, category, or description of a known product
  • • Agent returns only fields that exist in the store database
  • • Missing fields are reported as not available, not guessed
  • • Raw SQL and internal IDs are not shown unless already part of the store UI
Category Questions (FR-ATS-003)

Users can ask which categories exist and which products sit in a category

Acceptance Criteria:

  • • User can ask "What categories do you have?"
  • • Agent lists categories that exist in the database
  • • User can ask to show products in a selected category
  • • Empty categories return a clear no-data message

📦 Stock and Sales Totals

Stock Check (FR-ATS-004)

Users can ask for stock of a selected product

Acceptance Criteria:

  • • User can ask "Show the stock for [product]"
  • • Agent reads the current stock value from the existing database
  • • Zero stock is reported as zero, not as invented availability
  • • The agent does not reserve, increment, or decrement stock
Sales and Order Totals (FR-ATS-005)

Users with permission can ask for order counts and sales totals

Acceptance Criteria:

  • • User can ask "How many orders are there?"
  • • Totals come from existing order and order-item tables
  • • Date-range questions use only stored order dates
  • • The agent does not create or cancel orders

📋 Customer and Order History Questions

Customer Counts (FR-ATS-006)

Permitted users can ask how many customers exist

Acceptance Criteria:

  • • User can ask "How many customers are there?"
  • • Existing authorization decides what customer data is visible
  • • Passwords, tokens, and secrets are never returned
  • • The agent does not create or edit customer records
Order History Questions (FR-ATS-007)

Users can ask about orders they are allowed to see

Acceptance Criteria:

  • • User can ask about order count, status, or items for allowed orders
  • • Answers respect the existing login and role
  • • No matching order returns a no-data message
  • • The agent does not place, update, or cancel orders

🛡️ Safe Behavior and Refusals

Out-of-Scope Refusal (FR-ATS-008)

The agent only answers agreed store questions

Acceptance Criteria:

  • • Unrelated questions get a polite refusal
  • • Requests to change the cart, checkout, or database are refused
  • • Prompt-injection attempts are refused
  • • Unclear store questions ask for clarification instead of guessing
Ask Endpoint (FR-ATS-009)

The existing FastAPI backend exposes POST /agent/ask

Acceptance Criteria:

  • • Endpoint accepts a simple user question
  • • Existing authentication is required
  • • Invalid input, failures, and timeouts return a safe message
  • • Secrets, SQL, stack traces, and system prompts are never returned
Existing Store Unchanged (FR-ATS-010)

Ask the Store is added to the current application, not a new store

Acceptance Criteria:

  • • No second backend or second database is created
  • • Existing customer, cart, checkout, and admin APIs stay unchanged
  • • The React chat UI lives inside the existing frontend
  • • LangGraph runs inside the existing FastAPI backend
