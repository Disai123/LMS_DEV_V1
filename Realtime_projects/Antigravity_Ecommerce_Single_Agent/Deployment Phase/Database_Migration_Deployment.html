Database Access for Deployment

Ask the Store uses the existing PostgreSQL/Neon database. Deploy the agent without creating a second schema and without writing store data. Existing product, category, customer, order, and stock tables already hold the answers.

What stays in place

  • Existing products, categories, customers, orders, order items, and stock
  • Existing FastAPI database connection
  • Existing login tables and roles

What not to do

  • Do not create a second database for the agent
  • Do not add cart-write tables for the agent
  • Do not run a new migration set unless the existing store already needs one
  • Do not put real DATABASE_URL values in DEPLOYMENT.md

Deploy check

After Render starts, ask "How many products are in the store?" and compare the answer with a read of the live database. If the number does not match, fix the read-only path before calling the release complete.
