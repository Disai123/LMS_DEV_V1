Database Design

The database schema for the AI agent focuses on storing conversation history and messages. It integrates with existing e-commerce tables (User, Product, CartItem) to provide context for AI interactions.

💬 Conversation Model 

model Conversation {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id])
  title     String?  // Auto-generated from first message
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  
  messages  Message[]
  
  @@index([userId])
  @@map("conversations")
}
Key Fields:
  • id: Unique conversation identifier
  • userId: Links to User table (one-to-many)
  • title: Optional title for conversation
  • messages: One-to-many relationship with Message

📝 Message Model 

model Message {
  id             String       @id @default(cuid())
  conversationId String
  conversation   Conversation @relation(fields: [conversationId], references: [id], onDelete: Cascade)
  role           String       // "user" | "assistant"
  content        String       @db.Text
  toolCalls      Json?        // Store tool calls if any
  createdAt      DateTime     @default(now())
  
  @@index([conversationId])
  @@index([createdAt])
  @@map("messages")
}
Key Fields:
  • id: Unique message identifier
  • conversationId: Links to Conversation (many-to-one)
  • role: "user" or "assistant" (AI response)
  • content: Message text content
  • toolCalls: JSON field storing tool call metadata
  • createdAt: Timestamp for ordering messages

🔗 Relationships

User → Conversation

One user can have many conversations. Each conversation is isolated per user.

Conversation → Message

One conversation contains many messages. Messages are ordered by createdAt.

Integration with E-commerce Tables

Tool modules query Product, CartItem, Category tables for AI responses. No direct foreign keys, accessed via Prisma queries.

📊 Indexes & Performance

Conversation Indexes
  • userId (for user queries)
  • createdAt (for sorting)
Message Indexes
  • conversationId (for loading messages)
  • createdAt (for chronological order)
