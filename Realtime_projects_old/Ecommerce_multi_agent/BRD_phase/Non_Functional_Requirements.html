Non-Functional Requirements

Non-functional requirements specify the operational quality of the Multi-Agent Assistant, focusing on performance, security, and reliability in an agentic context.

Performance & Latency

  • • Reasoning latency for a single turn should not exceed 3 seconds.
  • • Tool execution (Search/Cart) must return results within 500ms.
  • • The UI must stream tokens to the user to reduce perceived latency.

Security & Privacy

  • • Zero-trust model: LLMs never see raw database credentials or private PII.
  • • All tool inputs must be strictly validated against Pydantic schemas.
  • • API endpoints must be protected with modern authentication headers.

Scalability

  • • The graph state must be persistable in a database to scale horizontally.
  • • Support for multiple concurrent shopping sessions per user with thread separation.
  • • Asynchronous tool calling to prevent blocking the supervisor's reasoning loop.

Reliability

  • • Graceful degradation if a worker fails (Supervisor must handle tool errors).
  • • Rate limiting on API calls to prevent agent hallucination loops from exhausting resources.
  • • Regular backup of agent state and conversation history.
