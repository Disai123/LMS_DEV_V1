Database Schema & Persistence

The Trip Planner utilizes a relational schema to manage user preferences, travel history, and cached MCP tool data. This ensures high performance and offline-first capabilities for core discovery.

Travel Management Schema

CREATE TABLE itineraries (
    id UUID PRIMARY KEY,
    user_id UUID,
    title TEXT,
    start_date DATE,
    end_date DATE,
    center_lat FLOAT,
    center_lon FLOAT,
    created_at TIMESTAMP
);

CREATE TABLE locations (
    id UUID PRIMARY KEY,
    itinerary_id UUID REFERENCES itineraries(id),
    name TEXT,
    osm_id BIGINT,
    lat FLOAT,
    lon FLOAT,
    category TEXT, -- cafe, museum, hotel
    visit_order INT
);

CREATE TABLE weather_cache (
    id SERIAL PRIMARY KEY,
    lat FLOAT,
    lon FLOAT,
    forecast_json JSONB,
    updated_at TIMESTAMP
);
Relational Integrity

Cascading deletes ensure that if an itinerary is removed, all associated locations and route markers are cleaned up automatically.

Caching Strategy

The weather cache reduces API costs by storing forecasts for coordinates within a 5km radius for up to 6 hours.
